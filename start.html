简介

Atmosphere 是一套面向民间自发漂流活动与野外游泳区域的低成本、高实效智能监测预警系统。

它通过部署在溪流/漂流点的传感器单元，实时采集土壤湿度、水流速、风速、温湿度等环境数据，用多因子数学模型判定山洪与泥石流风险等级（0~3 级），并通过网页监控 + 现场 LCD 双端呈现，在危险来临前为现场人员争取撤离时间。

⚠️ 本系统是辅助决策工具，不替代救生员与现场安全管理。山洪预警的黄金法则是上游预警——请结合上游雨量/水位遥测站构成完整预警链。

优势

实时监测

多传感器同步采集土壤湿度、水流速、风速、温湿度等环境数据

多因子数学模型判定山洪与泥石流风险等级（0~3级）

双端呈现

网页监控+现场LCD双通道预警，确保信息及时送达

低成本

采用开源硬件方案，适合民间自发漂流活动区域部署

高时效

在危险来临前为现场人员争取宝贵撤离时间

易部署

预警模型

等级体系（数字越大越严重）：0 = 正常 / 1 = 一级 / 2 = 二级 / 3 = 三级

滑动基准

24h 窗口 [P10,P95] 归一化，冷启动 15 分钟。

滞回防抖

预警触发后保持（一级 10s / 二级 15s / 三级 20s），避免等级闪烁。

常见问题

Q1：水泵一开 Arduino 就重启/断连？

水泵不能从 Arduino 5V 取电（会拉垮 5V → CH340 掉电 → 板子复位）。必须独立 5V 电源，GND 与 Arduino 共地，D9 只发 PWM 信号。

Q2：LCD 不亮 / 花屏？

① 检查 I2C 地址（默认 0x27）；② 确认 SCL→A5、SDA→A4 没接反；③ 旋转背光电位器调对比度。

Q3：流速一直为 0？

YF-S401 最小启动流量 0.3 L/min，低于此值转子不转（吹气测不了，必须通水）。

Q4：风速数值异常 / 静止也有读数？

三杯式风速计部分型号存在零点偏移，可在固件里做零点校准。

Q5：预警一直不触发？

① 土壤 <60% 时泥石流路径跳过（正常）；② 滑动基准冷启动需 15 分钟；③ 检查 D/F 数值是否在阈值附近（0.45/0.55/0.75）。

beta1 技术文档

一、项目简介

AtmoWave Technology 是面向野外溪流/漂流点的山洪 + 泥石流智能监测预警系统。Demo 1 实现：土壤湿度、流速、风速三路环境采集 + 水泵控制 + Web 实时监控 + 预警数学模型。

二、硬件连接方式

  • 主控：Arduino Nano（ATmega328P，新 Bootloader）
  • 土壤湿度传感器：AO→A2（模拟量），DO→D2（数字/断线检测），VCC→5V，GND→GND
  • 流速传感器 YF-S401：红线→5V，黄线→D8（信号），黑线→GND
  • 水泵：接 D7（高电平抽水，低电平停止）
  • 风速传感器（三杯式，0~5V）：接另一台电脑的 Arduino UNO A0，经 HTTP 转发到本机

三、软件实现

两个文件：FlowSensor.ino —— Arduino 固件；server.py —— Python Web 服务（端口 8080）。串口命令：发送 1 开泵 / 0 关泵。

四、预警模型

泥石流危险指数 D = 0.40·S̄ + 0.30·Q̄ + 0.20·dQ̄ + 0.10·ΔS̄

预警档位：🟢 正常：D < 0.30；🟡 三级预警：0.30 ≤ D < 0.55；🟠 二级预警：0.55 ≤ D < 0.75；🔴 一级预警：D ≥ 0.75

五、运行方式

编译上传 FlowSensor.ino → 运行 python3 -u server.py → 浏览器打开 http://localhost:8080

六、已知问题

水泵从 Arduino 取电会导致供电不稳；山洪曼宁 70% 缺超声波水位传感器；尖峰检测阈值待实测标定。

算法 v1 技术文档

版本：v1（第一版）
算法名称：风速基准线 + 滑动基准预警模型

一、算法总览

本版算法由 5 条独立预警路径组成，每秒计算一次，最终等级取各路径最高值：

最终等级 = max(泥石流 D, 山洪 F, 风速, 流量尖峰, 突变) 等级定义：0 = 正常 / 1 = 三级预警 / 2 = 二级预警 / 3 = 一级预警（一级最严重）

二、五条预警路径

1. 泥石流路径（四因子加权）

D = 0.30 × S̄ + 0.35 × Q̄ + 0.20 × dQ̄ + 0.15 × ΔS̄
因子含义归一化方式
S̄土壤湿度水平滑动基准 [P10,P95] 归一化
Q̄流量水平滑动基准归一化
dQ̄流量变化率min(变化率/5 L/min/s, 1)
ΔS̄土壤 10 分钟涨幅min(涨幅/15%, 1)

2. 山洪路径

F = 0.60 × Q̄ + 0.40 × dQ̄

不受土壤门槛限制，流量暴涨即触发。

3. 风速路径

风速等级
≥ 25 km/h三级
≥ 40 km/h二级
≥ 60 km/h一级

4. 流量尖峰路径

每秒流量变化率与当地 24h 历史分布对比，超 P95 视为高风险。spike_risk ≥ 0.8 → 三级；≥ 1.0 → 二级。

5. 突变路径（秒级响应）

土壤 5 秒内涨 ≥ 20% → 立即三级；风速 60 秒内涨 ≥ 12 km/h → 立即三级。

三、滑动基准

24 小时窗口，每分钟采样 1 点。把当前值映射到该地点历史 [P10, P95] 区间的 0~1 相对位置，自适应当地气候。

四、优势

  • 自适应强：滑动基准让同一套算法在不同气候区都能用
  • 多路径互不干扰：一条失灵不影响其他
  • 突变秒级响应：突发场景不用等 5-10 分钟窗口
  • 简单直观：全部是加权+阈值，好部署、好调试
  • 冷启动可用：基准数据不足时自动回退绝对值

五、缺陷

  • 山洪曼宁 70% 分量缺失（缺超声波水位传感器）
  • 风速阈值固定，未按当地风气候做滑动基准
  • 土壤 <60% 硬门槛可能漏报
  • 冷启动窗口期 2 小时
  • 流量传感器量程窄（YF-S401 仅 0.3-3 L/min）
  • 分级是硬阈值，无置信度输出

算法 v2 技术文档

版本：v2（第二版）
算法名称：传感器标定对齐 + 快速滑动基准预警模型

一、v2 相对 v1 的改动

项目v1v2原因
预警等级命名1=三级 / 3=一级0=正常 / 1=一级 / 2=二级 / 3=三级等级体系规范：数字越大越严重
泥石流权重0.40S+0.30Q+0.20dQ+0.10ΔS0.30S+0.35Q+0.20dQ+0.15ΔS土壤易饱和降权重；流量升最高权重
Q_MAX30 L/min3 L/min对齐 YF-S401 实测量程
DQ_MAX5 L/min/s0.5 L/min/s实测秒级跳变 ~0.3
冷启动2 小时15 分钟更快自适应当地气候

二、算法结构

最终等级 = max(泥石流 D, 山洪 F, 风速, 流量尖峰, 突变, 土壤饱和) ← 0~3
等级含义触发示例
0正常各因子均低于阈值
1一级预警（最轻）D/F ≥ 0.45，或风速 ≥25 km/h
2二级预警D/F ≥ 0.55，或风速 ≥40 km/h
3三级预警（最严重）D/F ≥ 0.75，或风速 ≥60 km/h

1. 泥石流路径

D = 0.30 × S̄ + 0.35 × Q̄ + 0.20 × dQ̄ + 0.15 × ΔS̄

土壤 <60% 时跳过（山洪/风速不受限）。

2. 山洪路径（独立指数）

F = 0.60 × Q̄ + 0.40 × dQ̄

不受土壤门槛限制，流量暴涨即触发。

3. 风速路径

≥25 km/h → 一级；≥40 km/h → 二级；≥60 km/h → 三级。

4. 流量尖峰路径

秒级变化率超当地历史 P95 → 二级；≥0.8 归一化 → 一级。

5. 突变路径（秒级响应）

土壤 5 秒内涨 ≥20% / 风速 60 秒内涨 ≥12 km/h → 立即一级。

6. 土壤饱和路径（v2 新增）

土壤 ≥85% 或超当地 P90 → 至少一级（不依赖流量）。

7. 滞回保持（v2 新增，防抖）

升级立即生效；降级需超过保持时间 —— 一级 10 秒 / 二级 15 秒 / 三级 20 秒。

三、LCD 显示（v2 新增）

W12.3 S45% F0.50 ← 风速 km/h · 土湿度 % · 水流速 L/min ALARM:3 L3 ← 预警等级 0~3（0=正常，3=三级最严重）

四、优势

  • 流量数据真正参与推理：标定参数对齐传感器量程后，Q̄/dQ̄ 变成有效因子
  • 滑动基准快速启用：15 分钟冷启动
  • 等级体系规范：0~3 数字越大越严重
  • 现场可视化：LCD 实时显示四路核心数据
  • 诊断能力：脉冲双向沿计数 + 电平输出

五、缺陷

  • 流量计量程仍窄（YF-S401 仅 0.05~3 L/min）
  • 风速数据依赖外部电脑（192.168.1.200:8001）
  • 滑动基准 15 分钟仍可能不够稳
  • 突变阈值仍是经验值
  • LCD 仅 ASCII，无法显示中文

风速+温湿度模块

王立辉负责。野外溪流/漂流点山洪智能监测预警系统 —— 风速 + 温湿度监测单元。

模块组成

文件说明
01_WindSensor.ino风速传感器基础版：三杯式风速计 → 风速 km/h / m/s，超 10 km/h 板载 LED 报警
wind_server.py基础版配套转发服务：读串口 → HTTP :8001/wind 返回 JSON
风速+温湿度/完整版：风速 + DHT11 温湿度 + 网页仪表盘 + 智能预警

硬件接线

  • 风速传感器：红线 → A0，黑线 → GND（三杯式风速计，0~5V 模拟输出）
  • DHT11：v → 5V，s → D4，g → GND
  • 报警 LED：板载 D13

运行方式

# 1. 烧录 Arduino（完整版） # Arduino IDE 打开 风速+温湿度/02_WindTempHumidity.ino，选 Arduino UNO + 对应端口 # 波特率 9600，串口输出 CSV：电压,风速,温度,湿度 # 2. 启动转发服务（8001 端口） cd 风速+温湿度/server python3 wind_server.py # 3. 启动网页仪表盘（3000 端口） npm install node server.js # 浏览器打开 http://localhost:3000

架构

Arduino UNO（串口 9600，CSV 输出） │ ▼ wind_server.py ── 独占串口，解析数据，缓存最新值 │ HTTP :8001/wind → {"wind_kmh","wind_ms","temp","hum","time"} ▼ server.js ── 每 1 秒轮询 8001，加分预警引擎 + SSE 推送 │ ▼ 浏览器 http://localhost:3000（仪表盘：风速曲线 / 温湿度 / 阵风 / 30 分钟基准线 / 分级预警）

与综合监控联动

本模块的 http://<风速电脑IP>:8001/wind JSON 接口被综合监控网页（土壤湿度 + 流速 + 水泵）调用，显示风速、温度、湿度；10 秒无响应自动判为离线。
